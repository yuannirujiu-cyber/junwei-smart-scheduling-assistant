## 0. 先把话说清楚：这是「可解释的启发式」，不是全局最优

赛题与设计文档都没有要求、也没有提供做全局最优所需的条件（真实换型矩阵、工艺路线、下游排队预测）。
设计文档 §12 自己写明：「本算法是可实现、可解释的启发式初版，不是全局最优算法」。
因此本文与流程图统一按下面这个口径描述，**不声称最优解**：

| | 内容 |
|---|---|
| **保证** | 硬约束永不被静默放宽 · 每个任务都给得出适配依据与工时公式 · 同一输入必得同一输出（确定性）· 风险显式分级 |
| **不保证** | 全局最优 · 所有订单必然按期 · 换型总时长最小 · 设备占用率最优 |
| **它是什么** | 在明确的目标序下，用「单步前瞻 + 设备预约」求出的一版**可行、可解释、可复现**的计划 |

如果一定要给一个「最优」的说法，准确表述是：**在给定目标序与贪心策略下的局部最优派单**——
每次机台空闲时，在候选订单中选出「约束余量最小」的那个，并对「立即换型」与「等下一台」做一次前瞻比较，
取预计完成更早且仍然可行的方案。它不做回溯，也不做多步搜索。

## 1. 目标序（这是全部取舍的判据）

企业在手册里给的目标顺序是分层级的，算法严格按这个层级做取舍：

```
第一优先  满足硬约束          R1 设备适配 / R2 日历 / R3 R4 换型判定 / R5 换型 1-5h
                              R6 工序间隔 <= 72h / R7 必填字段 / R8 交期政策
第二优先  提升准时交付率      能准时就不要迟到；迟到时优先减少迟到单数
第三优先  减少延期时长        同样迟到，优先缩短迟到小时数
第四优先  改善利用率与换型    前三条不受影响时，才用换型代价做最后排序
```

落到代码里，`compareCandidate` 的排序键依次是：
**约束余量 min(S, G) → 更早交期 → 更早下达 → 订单号**。
换型代价不作为排序主键，而是通过「同型号优先」（优先挑不用换型的订单）间接体现。

## 2. 输入与输出

### 2.1 输入（数据快照）

| 字段 | 含义 | 缺失时的行为 |
|---|---|---|
| `orders[]` | 订单号 / 规格 / 数量 / 预发货日 / 结束码 | 缺订单号 · 规格 · 数量 · 预发货日 → R7 阻断，**不排产且保留在交付率分母** |
| `machines` | 拉丝 47 台 / 捻股 51 台 / 合绳 11 台 | 某工序无设备 → 该工序全部订单阻断 |
| `capacity` | 捻股与合绳的「规格 × 机台」产出矩阵（米/分） | 矩阵空值 = 该机台不适配该规格，**绝不补 0、不补均值** |

### 2.2 中间结构（`buildModel` 产出）

```
jobs[] = 一张可排订单
  order      : { id, due, duePolicy, graceHours, allowLatest, sortKey, ... }
  ops[]      : 三道工序，按工艺链顺序
      process   : drawing | stranding | closing
      qty       : 该工序需求量（米）
      specCtx   : 适配判定与换型判定所需的规格上下文
  blocked[]  : 因缺口被阻断的订单（含缺口字段与修复建议）
  excluded[] : 被显式排除的订单（一键收敛的结果，进导出首页）
```

各工序需求量（`resolveMapping`）：

```
合绳需求量 = 订单米数 x 1.00
捻股需求量 = 合绳需求量 x 股数 x 1.02   （捻缩系数）
拉丝需求量 = 捻股需求量 x 丝数 x 1.02   （拉丝损耗）
加工时长(分钟) = ceil(需求量 / 机台单位产出)
```

> 注意：`股数 / 丝数 / 各系数` 中，股数与丝数来自订单规格解析（`token 形如 8*K26WS+IWRC`），
> 系数属于**数据包未提供、当前以显式标注的演示参数补齐**的部分（见 `../README.md` 诚实边界）。

### 2.3 输出

| 产物 | 内容 |
|---|---|
| `tasks[]` | 每道工序一条：订单号 / 工序 / 机台 / 配置键 / 就绪时间 / 换型起止 / 加工起止 / 换型分钟 / 派单时交期余量 / 上工序完工 / 工序间隔 / 预约原因 / 风险标签 |
| `unscheduled[]` | **没排进去**的工序及原因 |
| `anomalies[]` | **排进去了但触碰约束**的工序（超 72h / 预计延期 / 让位）——与未排严格分开 |
| `validation` | 三级风险（阻断 / 警告 / 提示），`canConfirm = 阻断数 == 0` |
| `metrics` | 准时交付率 · 延期单数与小时 · 设备计划占用率 · 加工利用率 · 换型总时长 |

## 3. 五个阶段（与流程图 ①～⑤ 一一对应）

### 阶段 ① 订单进入与数据接入

空白启动：应用不预置任何数据，订单与设备产能都必须来自上传或显式深链。
订单与设备两部分**都到位**才建立数据快照并自动首排；只到位一半时不排产，页面直接写出还缺哪一份。

### 阶段 ② 工艺映射与建模

1. **R7 校验**：订单号 / 规格 / 数量 / 预发货日缺一不可。缺交期必须真正阻断，
   否则会出现「D01 标为阻断、排产却照排并计入交付率分母」的自相矛盾。
2. **buildCapacity**：设备台账 → 规格区间与拉速；产能矩阵 → 每台机每分钟产出米数。
3. **resolveMapping**（成品规格 → 三道工序）：
   - 合绳规格：订单规格做**归一化键**（直径 + 括号内结构，统一去空格并大写）后在产能矩阵里匹配；唯一命中即自动关联，多命中按品名相似度择一并标注待确认。
   - 捻股股型：由**股径几何推导** `d ≈ πD / (n + π)` 得到目标股径，再在矩阵里按最近邻 + 丝数/涂层相似度择优。
   - 拉丝单丝直径：`股径 / sqrt(丝数)`。
   - 任何一步找不到 → R1 缺口 → 阻断，**不猜测、不套用不存在的机台**。
4. **buildModel**：产出 `jobs[]`，每张订单展开成三道工序。

### 阶段 ③ 前瞻派单核心（本算法的重点）

#### 3.1 事件驱动

不是每 10/5/15 分钟凭空放出一台设备，而是**按真实事件推进**：订单就绪、机台加工完成。
同一时刻的事件先批量处理，再对**所有**空闲机台统一派单——
从空白工厂起步时多台机台同时空闲，也必须同一时刻联合分配，**不人为错开**。

> 设计文档里的 10 / 5 / 15 分钟只是「缺少预测信息时的参考间隔」。
> 本实现从不据此虚构空闲设备或承诺订单可以等待：**只有核实过的、可预约的机台才算数**。

#### 3.2 候选筛选（三条缺一不可）

```
本工序已就绪        上一道工序已完工（或订单已下达）
机台兼容            规格区间 / 产能矩阵判定为可加工
未被占用            未被其他机台排产，也未被其他机台的预约锁住
```

#### 3.3 两个余量：S 与 G

```
S（交期余量） = 交期 - [ 本工序及下游各工序的名义加工时间之和
                        + 本工序及下游各工序的最坏换型之和 ]   （单位：分钟）

G（工序间隔余量） = 上工序完工时刻 + 4320 - 本工序实际开工时刻      （仅捻股 / 合绳）
```

- `S < 0` 表示在当前估计下**已经没有额外等待空间**（注意：S 不含未知的下游排队时间，
  因此它只能用来排序与分级，**不能单独用来证明最终一定按期**）。
- `G` 对应 R6：相邻工序间隔不得超过 72 小时 = 4320 分钟。
- 排序用的「约束余量」取 `min(S, G)`；最终仍要**分别**检查这两条约束。

最坏换型的取值：拉丝固定 60 分钟；捻股 / 合绳 = 目标订单股数 × 10 分钟。

#### 3.4 分层与排序

| 层 | 条件 | 处理顺序 |
|---|---|---|
| 紧急可行 | `0 <= S < 阈值` | 第一优先 |
| 负余量 | `S < 0` | `AFTER_URGENT` 模式下第二优先；`DEFER` 模式下暂缓并记录原因 |
| 普通可行 | `S >= 阈值` | 最后 |

阈值默认 **拉丝 1500 / 捻股 1080 / 合绳 600 分钟**（25 h / 18 h / 10 h），全部可在排产设置里改。

层内排序：`约束余量 min(S,G) 最小 → 更早交期 → 更早下达 → 订单号`。

#### 3.5 决策（设计文档 §5.5 的四行，就是流程图里的四个动作）

```
d = 当前优先层中约束余量最小的订单（最紧急）
c = 当前优先层中「本机同型号（无需换型）且完全可行」的最紧急订单

D1: d 同型号 或 没有可行的 c   -> 动作 A：加工 d（必要时换型）
D2: d 有更早的可行下一台        -> 动作 B：本机加工 c（不换型）+ 把 d 预约到下一台
D3: d 在本机可行               -> 动作 C：立即换型加工 d（等待会违约或超 72h）
    否则                      -> 动作 D：本机让位给同层其他可行订单 + 登记风险
```

关于 D2 有一个容易误读的点：**「等待」不是让当前机台停着**，而是当前机台继续加工同型号的 c，
d 等待的是**另一台已经核实的机台**。预约一旦建立，那台机台空闲后优先兑现；
并且**不允许反复把同一订单推给未来的下一台**——只有找到「严格更早且仍满足全部约束」的可行方案，才允许转移预约。

#### 3.6 落位与可行性

```
B = max( 当前时刻, 订单就绪时间, 机台空闲时刻 )
A = B + 换型时长          （不换型时 A = B）
C = A + 加工时长          加工时长 = ceil(需求量 / 单位产出)，向上取整到分钟
E = C + 下游最坏预留       下游最坏预留 = 下游各工序的名义加工 + 最坏换型
```

候选方案必须同时满足：

1. 已释放、工序已就绪、机台兼容；
2. 无机台时间冲突、无订单重复分配；
3. `E <= 交期`；
4. 捻股与合绳：`A <= 上工序完工 + 4320`。

**满足不了怎么办**：这一点设计文档写得很明确——「若 72h 已无法满足，列为工艺间隔异常，**不能静默放宽**」。
注意这句话约束的是「不许悄悄放宽」，不是「把订单丢掉」。因此本实现的处理是：

- 仍然把工序排进去，同时在任务上打风险标签、写进 `anomalies`，由校验报为**阻断级风险**；
- 若该订单连计划窗口都排不进去，则记为 `unscheduled`，并让本机先做同层其他可行订单（不空转）。

#### 3.7 换型判定与换型时长

| 工序 | 配置键 | 相同时 | 不同时 |
|---|---|---|---|
| 拉丝 | （原料规格，成品规格） | 不换型 | 固定 60 分钟 |
| 捻股 / 合绳 | （股数，结构，股径或绳径） | 不换型 | 目标订单股数 × 10 分钟 |

初始配置未知时**保守计一次换型**，不默认免费配置。
「股数 × 10 分钟」会被夹进赛题 R5 的 1–5 小时区间，越界值单独计数并在界面与文档中如实标注。

### 阶段 ④ 后处理 · 校验 · 指标

| 步骤 | 作用 | 不做的事 |
|---|---|---|
| `repairWaits` | R6 工序间隔修复：前序任务原地后移 / 换机台重放，把间隔压回 72 小时内 | 不新增设备，不放宽上限 |
| `improveSchedule` | 迟到恢复：在不产生新冲突的前提下把任务往前挪 | 每次提交前做整体占用与停机自洽性校验，不通过则整体回滚 |
| `refreshTraceFields` | 收尾归一化「上工序完工 / 工序间隔 / 换型段」字段 | 保证可追溯字段与任务实际位置永远自洽 |
| `validateSchedule` | 三级风险：阻断（阻止确认）/ 警告（需知晓）/ 提示 | 校验独立于求解过程重算 |
| `computeMetrics` | 准时率 / 延期 / 占用率 / 加工利用率 / 换型总时长 | 未排订单**保留在交付率分母** |

### 阶段 ⑤ 版本 · 人工干预 · 确认导出

- 生成候选版本（不可变快照 + 内容指纹），可与基线对比；
- 人工锁定（机台 + 起止）与执行冻结的任务**在重算中位置不变**；
- 存在阻断时确认按钮禁用——不许把有硬冲突的计划标成「已确认」；
- 一键收敛（有界）：反复排除阻断订单并重算，排除需明确勾选，排除清单进导出首页；
- 使用演示参数时，版本与导出文件持续标注「模拟结果，含未验证参数」。

## 4. 复杂度

| 环节 | 复杂度 | 实测（312 单 / 903 工序 / 109 台设备） |
|---|---|---|
| 映射与建模 | `O(订单数 x 工序数)` + 归一化键索引 `O(矩阵行数)` | 约 20 ms |
| 事件循环 | 事件数 `O(任务数)`；每个时刻对空闲机台各扫一遍候选 `O(空闲机台 x 可排订单)` | 首排约 121 ms |
| 下一台前瞻 | 仅在「d 需要换型且存在同型号 c」时触发，遍历同工序机台 `O(机台数)` | 预约约 93 次 / 兑现 89 次 |
| 后处理 | 每轮 `O(任务数 x 候选机台)`，轮数有界（默认 2） | 全流程约 200 ms |

## 5. 与设计文档的三处显式偏离

| # | 文档写法 | 本实现 | 为什么 |
|---|---|---|---|
| 1 | 加工时间固定 420 / 480 / 600 分钟 | 实际需求量 ÷ 机台产速 | 文档 §1.1 自己要求「若后续启用产品—机台产速匹配，应将加工时间替换为 实际长度 / 产速」。固定值只是初版估计 |
| 2 | 换型 = 股数 × 10 分钟 | 同公式，但夹进 R5 的 1–5 小时区间 | 股数 35 时 10n = 350 分钟 > 5 小时，违反赛题 R5。越界值单独计数并在界面标注 |
| 3 | 机台 `free_time` 语义（队列末尾追加） | 同样按队列末尾追加，不做间隙插入 | 保持与文档的预约数学一致；代价是机台之间的空档不会被后来的任务填满，已在 `../docs/ALGORITHM.md` 里量化 |

## 6. 实测结果（真实脱敏数据，312 张纳入订单）

| 指标 | 前瞻派单（本文算法，默认） | 按订单排程（原有实现，可切换对比） |
|---|---|---|
| 工序任务 | 903 条 | 903 条 |
| 预测准时交付率 | 96.5%（准时 301 / 纳入 312） | 96.5% |
| 预计延期订单 | 0 单 | 0 单 |
| **换型总时长** | **1617 小时** | 2050 小时 |
| 设备计划占用率 | 37.1%（加工利用率 34.8%） | 39.1%（35.9%） |
| 阻断级风险 | 18 项（R7 1 + R1 10 + R6 7） | 18 项（R6 7） |
| 首排耗时 | 约 121 ms | 约 90 ms |

换型总时长比原有实现低 **21.1%**（省 433 小时），准时率、延期单数与阻断级风险完全相同——
这就是「在可以安全等待时保持同型号加工」换来的收益：省下的换型时间不进交付率分子，但直接变成可用产能。

> 两套算法的**计划跨度不同**，占用率分母不同，因此 37.1% 与 39.1% 的差距里有一部分只是计划摊得更长，
> 不能单独当作「更省产能」的证据；能直接对比的是换型总时长与风险数量。

## 7. 已知限制

1. **不是全局最优**：贪心 + 单步前瞻，不做回溯、不做多步搜索、不求解整数规划。
2. **依赖平均与最坏估计**：S 用名义加工时间 + 最坏换型估计，不含下游真实排队时间，因此只能用于排序与分级。
3. **换型口径的两个细节**：派单器原始输出与最终上报的换型总时长完全一致（1,617 h / 771 条含换型，差 0.0 h）；
   但独立核验会发现 12 条任务的换型值与其「机台首个任务应保守计初始换型」的期望不一致（后处理换机台时的边界情形）。
   试过把这类候选一律拒绝，会让 R6 阻断从 7 处涨到 63 处；硬约束优先，因此保留现状并如实披露。
4. **预约机制有简化**：预约机台空闲即优先兑现，不处理「预约兑现之前先做别的活」。
5. **捻股配置键的结构维度会缺失**：部分股型记录的品名不含结构信息，配置键退化为 `股数|?|股径`；两侧都缺失时会判为同型号免换型。
6. **未接入真实换型矩阵与工艺路线**：换型时长、成品 → 股型映射、各工序需求量系数目前是显式标注的演示参数。
7. **下达时间口径**：引擎按 `materialReadyAt ?? 计划起点` 计算订单就绪；本数据包没有 `materialReadyAt`，若严格按订单日期下达需另行收紧。
