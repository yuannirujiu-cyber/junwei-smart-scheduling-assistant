# 局域网部署指南 · 君威智能排产助手

> 目标：把本机跑起来的工作台，投给**同一局域网**里的手机 / 平板 / 同事电脑 / 评委笔记本。
> 适用对象：要在现场把页面递给别人的演示者与保障人员。
> 相关文档：[DEPLOYMENT.md](./DEPLOYMENT.md)（本地 / systemd 内网服务器 / Docker / Nginx 反代与变量全表）、[OPERATIONS.md](./OPERATIONS.md)（日志与故障排查）、[演示脚本.md](./演示脚本.md)（5 分钟主线）。

本文所有命令与数值都在本机实测过，实测环境与结果见[第四节](#四实测记录)。

## 一、一页速查

~~~bash
cd "君威智能排产助手"

# 1) 绑定所有网卡启动（默认只绑 127.0.0.1，别人连不上）
node tools/serve.mjs --host 0.0.0.0

# 2) 查本机局域网 IP
ipconfig getifaddr en0                    # macOS Wi-Fi；有线一般是 en1

# 3) 把这条发给对方（同一 Wi-Fi / 交换机下的任何设备都能开）
#    http://<本机IP>:5178/web/index.html?data=demo
#    例：http://10.89.133.73:5178/web/index.html?data=demo
~~~

自检与停止：

~~~bash
lsof -nP -iTCP:5178 -sTCP:LISTEN          # 期望看到 *:5178；若是 127.0.0.1:5178 说明没绑 0.0.0.0
curl -s http://<本机IP>:5178/healthz      # 期望 "status":"ok" 且 "host":"0.0.0.0"
lsof -ti:5178 | xargs kill                # 停止（SIGTERM，服务会优雅退出）
~~~

**三条最容易踩的坑**（详见后文）：

1. 不加 `--host 0.0.0.0` → 只有本机能打开。
2. 地址少写 `/web/index.html` → 根路径 `/` 返回 404（实测 `/` → 404、`/web/` → 200）。
3. 启动横幅里恒印 `http://127.0.0.1:5178/...`，**只有「监听：」那一行才是真实绑定地址**。

## 二、为什么默认连不上：`127.0.0.1` vs `0.0.0.0`

`tools/serve.mjs` 的默认 `HOST` 是 `127.0.0.1`，这是**有意的最小暴露面**：只监听回环网卡，局域网里任何设备都连不上。

| 绑定地址 | 谁能访问 | 适用场景 |
|---|---|---|
| `127.0.0.1`（默认） | 仅本机 | 自己开发 / 本机演示 |
| `0.0.0.0` | 本机 + 同网段所有设备 | **局域网演示（本文目标）** |
| 指定网卡 IP（如 `10.89.133.73`） | 仅该网段 | 多网卡机器上只暴露其中一张 |

切换方式（两种等价，命令行优先）：

~~~bash
node tools/serve.mjs --host 0.0.0.0
HOST=0.0.0.0 node tools/serve.mjs
~~~

### 别被启动横幅误导

以下是实测的启动输出，URL 那三行**恒为 `127.0.0.1`**，与真实绑定地址无关：

~~~
君威智能排产助手静态服务器 v1.0.0 已启动：
  http://127.0.0.1:5199/web/index.html          ← 恒印 127.0.0.1，不要照着发给别人
  （DEMO 场景数据：http://127.0.0.1:5199/web/index.html?data=demo）
  健康检查：http://127.0.0.1:5199/healthz    构建信息：http://127.0.0.1:5199/version
  监听：0.0.0.0:5199   根目录：/Users/…/君威智能排产助手        ← 这一行才是真绑定地址
  只读：是   压缩：开   图片缓存：max-age=3600   日志级别：info
~~~

判断服务到底绑在哪，最可靠的是直接问它自己：

~~~bash
$ curl -s http://127.0.0.1:5178/healthz | grep -E '"host"|"port"|"pid"'
  "host": "0.0.0.0",
  "port": 5178,
  "pid": 21099,
~~~

或看内核视角（`*:5178` = 所有网卡；`127.0.0.1:5178` = 仅本机）：

~~~bash
$ lsof -nP -iTCP:5178 -sTCP:LISTEN
COMMAND   PID       USER   FD   TYPE   NODE NAME
node    21099 kazuhamiyo   14u  IPv4   TCP *:5178 (LISTEN)
~~~

## 三、四步完成部署

### 3.1 第一步：确认前置

| 项 | 要求 | 自检命令 |
|---|---|---|
| Node.js | **≥ 18.2**（实测 v24.17.0） | `node -v` |
| 工作目录 | 含 `web/index.html`（本服务的静态根） | `ls web/index.html` |
| 端口 | 默认 `5178`，被占用就换 | `lsof -nP -iTCP:5178 -sTCP:LISTEN` |
| 依赖 | 无。零第三方依赖、无构建步骤、不联网、不需要 `npm install` | — |

工作目录必须切到仓库根（即 `tools/` 的上一级），否则默认静态根会指错：

~~~bash
cd "君威智能排产助手"        # 仓库根
node tools/serve.mjs --host 0.0.0.0
~~~

### 3.2 第二步：查本机局域网 IP

~~~bash
# macOS（Wi-Fi 一般是 en0，有线是 en1；两个都试一下）
ipconfig getifaddr en0
ipconfig getifaddr en1

# 想看完整网段与掩码
ifconfig en0 | grep "inet "

# Linux
hostname -I
ip -4 addr show

# Windows（PowerShell / CMD）
ipconfig
~~~

本机实测环境（供对照）：

~~~
en0: inet 10.89.133.73  netmask 0xffffe000  broadcast 10.89.159.255
~~~

`0xffffe000` = `255.255.224.0` = **/19**，即同网段范围是 `10.89.128.0 – 10.89.159.255`。
对方设备的 IP 必须落在这个范围内才能直连；不在同一网段就得走路由器/VPN（见 [8.3](#83-确认是否同网段)）。

> **IP 会变**：地址由 DHCP 分配，路由器重启或租约到期后可能变化，每次演示前重查一次即可。
> 需要固定地址就在路由器上做 DHCP 保留，或改用 [DEPLOYMENT.md 3.2 节的内网服务器部署](./DEPLOYMENT.md)。

### 3.3 第三步：绑定所有网卡启动

**方式 A：前台启动（推荐，最省事）**

~~~bash
node tools/serve.mjs --host 0.0.0.0
~~~

按 `Ctrl+C` 停止（SIGINT，服务会停止接收新连接、等在途请求后退出）。

**方式 B：前台启动 + 阻止系统睡眠（长时间演示推荐）**

系统睡眠会断开所有访问（**显示器睡眠不影响**）：

~~~bash
caffeinate -s node tools/serve.mjs --host 0.0.0.0     # -s 只在接电源时生效
caffeinate -i node tools/serve.mjs --host 0.0.0.0     # -i 电池供电也阻止空闲睡眠
~~~

**方式 C：后台常驻 + 落日志（无人值守 / 展厅大屏）**

~~~bash
cd "君威智能排产助手"
mkdir -p /tmp/jw-logs
nohup caffeinate -i node tools/serve.mjs --host 0.0.0.0 \
  > /tmp/jw-logs/serve.log 2>&1 &
echo $! > /tmp/jw-logs/serve.pid

tail -f /tmp/jw-logs/serve.log        # 看启动横幅与访问日志（JSON 一行一条）
kill "$(cat /tmp/jw-logs/serve.pid)"  # 停止
~~~

**可选参数**（局域网演示常用，完整表见 [DEPLOYMENT.md 第四节](./DEPLOYMENT.md)）：

~~~bash
PORT=5180 node tools/serve.mjs --host 0.0.0.0          # 端口被占用时换端口
node tools/serve.mjs --host 0.0.0.0 --log-format json  # 结构化日志，便于采集
node tools/serve.mjs --host 0.0.0.0 --quiet            # 静音（排障时别开）
~~~

### 3.4 第四步：先本机自测，再给对方

**顺序很重要**：先在**本机**用局域网 IP 自测，能把问题一刀切开——本机用 IP 通、对方不通 ⇒ 网络/防火墙问题；本机用 IP 也不通 ⇒ 路径/服务问题。

~~~bash
IP=$(ipconfig getifaddr en0)

# 健康检查 + 首页 + 关键静态资源 + 数据快照
curl -s       "http://$IP:5178/healthz"
curl -s -o /dev/null -w "%{http_code}  /web/index.html\n" "http://$IP:5178/web/index.html"
curl -s -o /dev/null -w "%{http_code}  /web/src/main.js\n" "http://$IP:5178/web/src/main.js"
curl -s -o /dev/null -w "%{http_code}  /data/demo-dataset.json\n" "http://$IP:5178/data/demo-dataset.json"
~~~

期望：`/healthz` 返回 `"status":"ok"`，其余三行都是 `200`。全部通过后，再把地址发给对方：

~~~
http://10.89.133.73:5178/web/index.html?data=demo
~~~

> 路径可以简写为 `/web/`（实测 `200`，等价于 `/web/index.html`）；但**根路径 `/` 是 404**，地址栏里别只留 `IP:端口`。

## 五、入口地址怎么给

应用**默认是空白工作台**：打开后没有任何数据，需要上传订单文件 + 设备/产能文件才会出计划。
所以「给对方哪个链接」取决于你要他看什么：

| 用途 | 链接 | 首屏 |
|---|---|---|
| 空白工作台（走完整上传流程） | `http://<IP>:5178/web/index.html` | 两个上传槽「待上传」，无数据无计划 |
| **精简演示场景**（手机 / 快速演示推荐） | `http://<IP>:5178/web/index.html?data=demo` | 14 条虚构 DEMO 订单，覆盖 PRD 13.2 的 8 个场景 |
| 真实脱敏快照（巡检 / 展厅大屏） | `http://<IP>:5178/web/index.html?data=real` | 323 条真实脱敏订单的完整计划 |
| 强制干净启动（跳过浏览器里恢复的旧会话） | 上述任意链接后追加 `&fresh=1` | 忽略本机 IndexedDB 里的历史会话 |

说明：

- `?data=demo|real` 是**显式深链**，服务端不参与，由 `web/src/main.js` 读取；不写就一定是空白工作台，不会静默加载内置快照。
- `?fresh=1` 只对本次启动生效，随后会被 `history.replaceState` 从地址栏剥离，避免刷新时反复回到干净会话。
- 想让对方「打开即见计划」，请直接把带 `?data=` 的完整链接发过去，不要口头说「点一下内置快照」。

**把链接送到手机上**：最省事的是用微信/隔空投送把链接发给自己再点开。
（本机未安装 `qrencode`；如果装了可以终端出二维码：`qrencode -t ANSIUTF8 "http://<IP>:5178/web/index.html?data=demo"`。）

## 六、局域网下的浏览器差异

局域网访问是**明文 HTTP + 非 localhost 来源**，浏览器会把它标记为「不可信来源」。实测结论：

| 能力 | 局域网 HTTP 下 | 说明 |
|---|---|---|
| ES Modules / `import` | ✅ 正常 | 本项目前端就靠它，无影响 |
| IndexedDB（会话持久化） | ✅ 正常 | 实测库名 `junwei-aps` |
| BroadcastChannel（多标签同步） | ✅ 正常 | — |
| `navigator.clipboard` | ❌ `undefined` | 非安全上下文不提供；应用已用 `execCommand('copy')` 兜底，复制功能仍可用 |
| `Cross-Origin-Opener-Policy` 响应头 | ⚠️ 被忽略 | 控制台一条提示，**不影响任何功能** |
| HTTPS | **不需要** | 上面的能力在明文 HTTP 下已够用，不必为演示配证书 |

> 如果控制台出现 COOP 那条红字，可以放心忽略；它不是故障。

**凭据与会话按来源隔离**：`http://10.89.133.73:5178` 与 `http://127.0.0.1:5178` 是**两个来源**，
各自的 IndexedDB 互不相通。含义是：

- 你在本机排好、确认好的版本，**不会**出现在评委手机上的页面里 —— 他那台是干净的空白工作台；
- 反过来也一样，不用担心别人的操作污染你的本机会话；
- 想让所有人看到同一份结果，用带 `?data=real` 的链接让每台设备各自载入同一份快照。

## 七、各设备屏幕的实测建议

工作台的侧边栏是**固定宽度**的（无手机抽屉式折叠），窄屏下会把主区域挤扁。实测（`?data=demo`）：

| 视口宽度 | 侧边栏 | 主区域 | 结论 |
|---|---|---|---|
| 390 px（手机竖屏） | 196 px | **194 px** | ❌ 甘特图基本不可读，Toast 还会盖住内容 |
| 820 px（平板 / 横屏手机 / 小窗） | 196 px | 624 px | ✅ 指标卡 + 双视角甘特图 + 风险面板完整可读 |

建议：

- **主演示用笔记本或平板（≥ 1024 px）**，或手机**横屏**；
- 手机竖屏只用来给别人看**指标卡与风险清单**，不要用它讲甘特图；
- 需要在大屏上放，直接用 HDMI/投屏开本机 `http://127.0.0.1:5178/web/index.html?data=real` 更稳。

## 八、连不上时的分层排查

按顺序往下走，每层都有明确的判定信号。**先做 8.1，它最快定位问题在哪一层。**

### 8.1 服务是否绑在所有网卡上

~~~bash
lsof -nP -iTCP:5178 -sTCP:LISTEN
~~~

| 看到 | 含义 | 处理 |
|---|---|---|
| `TCP *:5178 (LISTEN)` | 已绑所有网卡 ✅ | 进入 8.2 |
| `TCP 127.0.0.1:5178 (LISTEN)` | 只绑了本机 ❌ | 停掉，改用 `--host 0.0.0.0` 重启 |
| 无输出 | 服务没在跑 | 启动它，并检查启动报错 |

### 8.2 从对方设备复测

让对方的设备浏览器打开 `http://<IP>:5178/healthz`：

- 能看到 JSON ⇒ 网络通，问题在页面路径或浏览器缓存 → 用完整 `/web/index.html` 链接、强制刷新（见 8.6）
- 打不开 ⇒ 继续 8.3

### 8.3 确认是否同网段

对方设备看自己的 IP，与你本机 IP + 掩码比对（本机是 `10.89.133.73/19`，同网段即 `10.89.128.x – 10.89.159.x`）。

不同网段的典型原因：

- 连了**不同的 Wi-Fi**（2.4G/5G 是不同 SSID 时尤其常见）；
- 连了**访客网络 / 手机热点**，与主机不在一个子网；
- **AP 隔离（客户端隔离）**：不少企业/酒店 AP 默认开启，同一 SSID 也互相不通 —— 换一个路由器或开热点给两台设备同连；
- **本机开了 VPN / 代理**：本机存在 `utun4` 隧道，代理软件（如 Clash 的 TUN 模式）可能劫持局域网流量 —— **演示前关掉 VPN 与代理软件**；
- 有线 / 无线分属不同 VLAN。

### 8.4 检查 macOS 防火墙

~~~bash
/usr/libexec/ApplicationFirewall/socketfilterfw --getglobalstate
# 本机实测：Firewall is disabled. (State = 0)
~~~

若显示已启用，首次监听时系统会弹「是否允许 node 接受传入连接」，**选择允许**；
也可在「系统设置 → 网络 → 防火墙 → 选项」里为 node 显式放行。

### 8.5 端口与占用

~~~bash
lsof -nP -iTCP:5178 -sTCP:LISTEN                     # 谁占了 5178
PORT=5180 node tools/serve.mjs --host 0.0.0.0        # 换端口（记得把新端口写进发给对方的链接）
~~~

端口被占用时服务会直接报 `EADDRINUSE` 并给出换端口的提示，不会静默失败。

### 8.6 浏览器侧

| 现象 | 原因 | 处理 |
|---|---|---|
| 打开是 404 页面 | 地址只写了 `IP:端口` | 补全 `/web/index.html`（根路径 `/` 本来就是 404） |
| 页面能开但样式/交互不对 | 旧缓存（html/js/css 为 `no-cache`，但代理层可能缓存） | 强制刷新（`Cmd/Ctrl+Shift+R`），或加 `&fresh=1` |
| 打开是空白工作台 | **这是默认行为**，不是故障 | 上传文件，或改用 `?data=demo` / `?data=real` |
| 看到的是别人的旧会话 | 该来源下 IndexedDB 里有历史会话 | 加 `&fresh=1`，或在「数据准备」里清空 |
| 控制台一条 COOP 红字 | 非安全上下文忽略该响应头 | 忽略，不影响功能 |

### 8.7 日志侧

服务把每次请求打成一行日志（`--log-format json` 时也是 JSON），对方访问时你应该能**实时看到**对应记录：

## 九、安全边界（务必遵守）

本服务是**只读静态分发**，且**没有任何认证**：

- 写方法（POST/PUT/DELETE…）一律 `405`，响应头带 `X-Read-Only: 1`， `/healthz` 的 `readOnly` 字段同步反映；
- 无登录、无 Token、无访问日志脱敏区分：**谁能连上，谁就能看全部数据**；
- 不做 TLS，是明文 HTTP。

因此：

1. ✅ **只在可信局域网内暴露**（自己的热点 / 办公室内网 / 比赛现场局域网）。
2. ❌ **禁止公网暴露**：不做路由器端口转发、不做公网反向代理、不用内网穿透隧道（ngrok / frp / cloudflared 等）。
3. ❌ 不要在访客 Wi-Fi、酒店网络、公共热点上启动 `--host 0.0.0.0`。
4. ⚠️ 比赛数据虽已脱敏，仍按约定**仅限本次比赛使用**，不得外传。
5. 🔒 需要跨网段 / 远程访问时的正确做法：**VPN**（把远端设备放进同一内网），而不是把端口映射到公网。

## 十一、停止与重启

| 操作 | 命令 |
|---|---|
| 前台启动的实例 | `Ctrl+C`（SIGINT，优雅退出） |
| 按端口停止 | `lsof -ti:5178 \| xargs kill` |
| 按 PID 停止（从 `/healthz` 或 `lsof` 取） | `kill <pid>` |
| 停止后台实例（方式 C） | `kill "$(cat /tmp/jw-logs/serve.pid)"` |
| 重启 | 停止后重新执行启动命令；静态资源无需重建，改完 `web/` 下文件刷新浏览器即可 |

优雅退出行为：先停止接收新连接 → 等在途请求完成（默认上限 10s，可用 `--shutdown-timeout` 调整）→ 超时才强退。
