# 路演演示脚本（建议 5 分钟主线）

> 启动：`node tools/serve.mjs` → 打开 http://127.0.0.1:5178/web/index.html
> 精简场景：http://127.0.0.1:5178/web/index.html?data=demo （14 条虚构 DEMO 订单，覆盖 PRD 13.2 的 8 个场景）

主线按「业务问题 → 数据准备 → 首排 → 双视角 → 解释/锁定/重算 → 急单对比 → 确认导出 → 价值边界」推进，
每一步都对应赛题手册的硬性要求，评委可当场核对。

---

## 0:00–0:40　业务问题与数据准备（D01）

1. 打开页面是**空白工作台**（不预置任何数据）。演示上传：拖入《订单信息.xlsx》→ 人工确认字段映射 → 拖入《产品额定（平均值）.xlsx》→ 确认替换设备 → 系统自动建立数据快照并生成首排计划（323 条订单、47 台拉丝机 / 51 台捻股机 / 11 台合绳机）。
   > 若时间紧张，可直接点「比赛脱敏数据快照」按钮跳过上传；两条路径的结果完全一致（`tools/check_blank.mjs` 逐条断言）。
2. 点左侧「数据准备」→ 指出顶部**数据就绪摘要**：「可排 301 单 / 阻断 11 单 / 历史 11 单」（本次排产纳入 312 单）。
3. 指出**错误清单按行定位**：10 张订单的合绳规格在产能矩阵中无匹配记录、1 张订单缺预发货日 → 系统**不猜测、不丢单**，而是阻断并给出修复入口。
4. 指出「规格关联」表：订单原规格 → 解析后的绳径 / 结构 / 股数 → 归一化键 → 合绳候选 → 匹配状态。

> 讲点：这就是「数据能用」这一环。97% 的订单可自动关联，剩下 3% 显式暴露给计划员，而不是静默失败。

## 0:40–1:20　首排（D00 + D03）

5. 点左侧「排产设置」→ 快速展示 **R1–R10 规则摘要**，每条标注「已满足 / 待确认」，并诚实说明换型耗时矩阵与成品→股型映射数据包未提供，当前以**显式标注的演示参数**补齐。
6. 回到「排产工作台」→ 点右上「重新生成计划」，观察顶部「正在生成候选计划…」与阶段提示。
7. 结果：**预测准时交付率 96.5%（301/312）、预计延期 0 单、设备计划占用率 37.1%**，903 条工序任务，首排约 90 ms（对比现状「每天排一次、每次 2–4 小时」）。

## 1:20–2:00　双视角甘特图（D03）

8. 设备视角：拉丝 / 捻股 / 合绳分组，展开「空闲设备」看可折叠；指出**换型条（紫色斜纹）**与任务条分离显示、跨日任务不截断。
9. 切「订单视角」→ 展开一张订单 → 看到**父行 + 三道工序子行 + 前后序等待时长 + 交期标线**。
10. 切「周」缩放 → 点「定位今日」→ 说明时间轴支持小时 / 日 / 周与横向滚动。
11. 指出底部**图例固定可见**，风险用「图标 + 边框 + 斜纹 + 文字」四重表达，不只依赖红绿。

## 2:00–2:50　解释、锁定、重算（D04，硬性项 15%）

12. 点任意任务条 → 右侧抽屉打开：
    - 「安排」页签：机台、起止、工时、数量 ÷ 单位产出、换型、前后序等待、交期。
    - **点开「依据」页签**：结论 → 具体约束 → 证据 → 可操作入口；每条证据都写明**数据来源**与**命中的规则编号**（R1/R3/R4/R5/R6/R8/R9）。
    - 指出示例文案里的「换型触发字段」与「可选机台共 N 台，本次评估了 M 个可行位置」。
13. 点「锁定该任务」→ 回到工作台点「重新生成计划」→ 回到该任务，**机台与起止时间完全不变**。
14. 点「人工调整」→ 设备下拉框**只列出适配机台**；把开始时间往前调 → 立刻出现红色阻断「早于前序工序完工时间」→ 保存按钮禁用 → 说明**非法输入当场拦截，保留用户输入并指出原因**。

## 2:50–3:50　急单与异常重排（D06，进阶任务）

15. 点右上「模拟变更」→ 展示三类扰动：紧急插单 / 设备故障 / 物料延迟（每周约 5 次的真实频率）。
16. 选「紧急插单」→ 表单已按演示场景预填 → 点「生成候选方案」。
17. 展示**两张真实求得的候选卡**：「候选A · 交期优先」与「候选B · 尽量少调整」，对比指标包含：
    预测准时交付率、延期订单数、**新增延期**、**恢复准时**、硬交期冲突、**变化原订单数 / 变化工序数 / 累计开始时间偏移**、换型总时长。
18. 指出**逐单影响表**：「比原方案晚完成」与「超过交期」分开表达；新增急单单独列示，不计入原计划扰动。
19. 点「采用此方案」→ 生成**待确认版本**，基线版本保持不变。

## 3:50–4:30　确认与导出（D05）

20. 点右上「确认版本」→ **确认前检查弹窗**逐项列出：纳入 / 排除 / 未排 / 硬约束冲突 / 政策参数缺口 / 软交期风险 / 锁定数 / 是否已重算。
21. 有阻断时确认按钮禁用；点「查看阻断项」跳到对应任务。
22. 在「数据准备 → 范围确认」点**「一键收敛：排除阻断订单并重算」** → 系统自动反复「排除 → 重算」直到可确认
    （实测真实数据 5 轮、排除 38 张，中间草稿自动清理）→ 回到工作台点「确认版本」→ 勾选「已知晓延期」→ 确认成功。
    强调：排除是**显式**的，排除清单会出现在确认页与导出文件首页，不把局部成功展示为全部订单完成。
23. 「方案版本」页看到版本从「草稿 → 可确认 → 已确认」，旧版本自动标为「已替代」；点「复制为草稿」派生新版本。
24. 点「导出」→ 展示四类导出；强调每个文件开头都写明**版本号、数据快照、导出时间、排除清单与「模拟结果，含未验证参数」标识**。

## 4:30–5:00　负荷分析与价值边界（D07）

25. 点左侧「负荷分析」→ 顶部显著标注「**计划推算，不是 MES 实际实绩**」；三工序负荷对比显示**捻股 53.2% 为瓶颈工序**。
26. 点某台高负荷设备「定位到工作台」→ 跳回甘特图并选中该设备。
27. 收尾诚实边界：
    - 换型耗时、工艺映射、各工序需求量系数为**演示参数**，界面与导出持续标注；
    - 「合绳完工」是**交付预测代理指标**，不等于实际发货；
    - 未接 ERP / MES，确认仅表示本产品内的人工认可；
    - 剩余阻断项（工艺映射缺口、R6 等待超限）是**真实能力边界**，系统显式阻断而不是伪装成功。

## 可能被问到的问题与答案

| 提问 | 回答要点 |
|---|---|
| 排产是不是黑盒？ | 每个任务都有「依据」页签，写明适配判定、工时公式、换型触发字段与来源、排序依据和命中的规则编号；无证据的原因显示「需要核实」，不做「最优」这类无依据断言。 |
| 人工怎么干预？ | 完整锁定（机台 + 起止时间）后重算保持不变；调整表单只列适配机台、结束时间由产能重算、冲突当场拦截；全部变更进入变更记录并可撤销。 |
| 交期和效率冲突怎么办？ | 权重口径是「先满足硬约束 → 提升准时交付率 → 减少延期时长 → 改善利用率 / 减少换型」；换型只在同等交期下优化，不提供可绕过硬约束的滑杆。 |
| 数据不全怎么办？ | 不猜测。矩阵空值一律视为不适配；缺映射的订单阻断并列出修复入口；确实需要演示参数时显式开启「演示参数模式」，记录参数值、依据、操作者，且不进入正式已确认状态。 |
| R6 等待超限为什么还有阻断？ | 那是真实的能力耦合：捻股任务平均约 2 天，部分订单在 72 小时内等不到下游机台。系统按 PRD 要求显式阻断确认，并提供「排除全部阻断订单」一键缩小范围后重算，绝不静默放宽。 |
| 性能如何？ | 312 张订单 / 903 条工序任务 / 109 台设备，首排约 90 ms，全流程约 170 ms（Node 实测，数据见 README）。 |
