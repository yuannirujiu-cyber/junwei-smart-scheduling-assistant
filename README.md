# 君威智能排产助手 · Web 工作台

钢绳索具工厂**多工序智能排产工作台**的可运行网页原型。按《第七期 Hello Hackathon AI排产赛题手册》R1–R10 规则与《君威智能排产助手_产品PRD_V1.0》的页面 / 交互 / 验收要求实现。

> 一句话定位：把订单排到**具体机台与时间**、**解释安排依据**、支持**人工调整并评估变更影响**的智能排产工作台。

---

## 一、快速运行

**零依赖**：不需要 npm install，不需要联网，不引用任何 CDN，只有原生 ES Modules。

~~~bash
cd "君威智能排产助手"
node tools/serve.mjs
# 浏览器打开 http://127.0.0.1:5178/web/index.html
~~~

**打开时是空白的**：不预置任何数据，没有订单、没有设备、没有排产结果。流程是「上传文档 → 解析处理 → 页面显示」：

1. 拖入**订单文件**（订单信息.xlsx / .csv）→ 自动建议字段映射 → **人工确认**后入库；
2. 拖入**设备 / 产能文件**（《产品额定（平均值）.xlsx》）→ 确认设备台数与矩阵行数后替换；
3. 两部分齐备 → 自动建立数据快照 → 自动生成首排候选计划 → 跳到排产工作台。

只上传一半时**不会排产**，页面明确写出还缺哪一份（不拿半份数据出计划）。也可以随时：**清空并回到空白**、导入一份 .json 数据快照、或点按钮直接载入内置快照。

- **内置快照（演示用，非默认路径）**：比赛脱敏数据包 323 条真实脱敏订单 / 47 台拉丝机 / 51 台捻股机 / 11 台合绳机 —— 点「比赛脱敏数据快照」按钮，或访问 http://127.0.0.1:5178/web/index.html?data=real （显式深链）。
- 精简演示场景：http://127.0.0.1:5178/web/index.html?data=demo （14 条虚构 DEMO 订单，覆盖 PRD 13.2 要求的 8 个场景）。
- 上传真实源文件与载入内置快照**结果完全相同**：`tools/check_blank.mjs` 逐条断言两条路径的任务集合（订单 × 工序 × 机台 × 起止）一致。
- 必须用 HTTP 打开。file:// 直接打开会被浏览器的模块与 fetch 同源策略拦截。
- 端口被占用时：`PORT=5180 node tools/serve.mjs`。

#### 顺带修掉的一个通用交互缺陷：连续输入被反转

做库存输入框时发现：视图层是「整块 innerHTML 重渲染」，凡是**在 `input` 事件里调用 `rerender()`** 的输入框，
每敲一个字就重建一次 DOM —— 输入框丢焦点、光标回到开头，于是连续输入被反转。实测：

| 输入框 | 逐位输入 | 修复前 | 修复后 |
|---|---|---|---|
| 材料库存 | `1` `2` `3` `4` | `4321` | `1234` |
| 甘特关键字 | `2` `6` `0` | `062` | `260` |

修法分三层（都在 `main.js`，有回归断言）：

1. **渲染前后保存/恢复焦点与光标**（`captureFocus` / `restoreFocus`）——文本输入框的光标位置可以精确还原；
2. **输入过程中做 300ms 防抖**，停止输入后再重渲染一次 —— 这是 `input[type=number]` 的根治办法，
   因为它不支持 `setSelectionRange`，光标位置无法还原；
3. 数字框聚焦后光标会停在**开头**，用「清空再写回」把它推到末尾 —— 否则输完停顿一下再继续输入会插到最前面
   （实测 `1234` 停顿后输 `56` 得到 `561234`）。

### 材料库（D08）怎么工作

- **用料判定基于订单真实字段**，不是黑箱：品名 / 规格含「镀锌」→ 锌锭；含「铝合金」→ 锌铝合金；
  含「注塑 / 涂塑」或绳芯为 PIWRC / PWSC → 塑料；绳芯 FC → 纤维芯；绳芯 IWRC / WSC → 铁（低碳钢芯料）；
  涂层含「涂油」→ 润滑油脂；所有订单都需要钢材（拉丝母材）。每条判定都带可读依据，界面上逐条可见。
- **默认全部有货**：只有显式把某种材料标为「无」才会阻断订单 —— 装上这个门禁，既有数据集的结果一字不变（301 可排 / 11 阻断）。
- **缺料 = 订单异常**：需要缺料材料的订单立刻整行标红（订单中心「材料」列 + 整行红底），进阻断清单，
  **不产生任何工序任务**；同时把已有计划标记为「存在未重算的修改」，避免在缺料状态下直接确认计划。
- **可逆**：恢复为「有」并重新生成计划，即回到原状（实测 903 条任务 / 0 缺料阻断）。
- **储备统计**：库存与安全库存为人工台账；**只有钢材有几何用量估算**（`π(d/2)² × L × 7.85 g/cm³`，按单丝直径与拉丝需求量换算），
  锌 / 铝 / 塑料 / 油脂的消耗定额数据包未提供，页面显示「未提供定额」，**不编造用量**。

### 当前日期（排产参考「今天」）

顶栏常驻一个日期控件：**修改后甘特图的「今日」高亮、now 参考线与「定位今日」都会落在该日期上**。

- **默认跟随系统日期**，行为与以前完全一致；只有人工改过才生效，并标注「模拟」+ 一键恢复。
- 数据是历史窗口（例如计划起点 2026-08）时，系统真实日期落在窗口之外，参考线根本没有落点；
  改这个日期就能把参考线放回窗口内。参考日期**不在计划窗口内**时控件标红并提示「窗口外」。
- 它是**参考线**：只影响时间轴显示与定位，**不参与排产约束、不改变任何任务**
  （回归断言直接比对改前改后的任务数必须相等）。

**统一硬性要求**的落地方式：

- **约束可解释**：每个任务都给得出「为什么是这台设备、这个时间」——适配依据、工时公式、换型触发字段与耗时来源、排序依据、命中的规则编号，全部来自结构化计算，不做无依据断言（无证据的原因直接显示「需要核实」）。
- **人工可干预**：D04 完整锁定（机台 + 起止时间）→ 重算保持不变；调整表单只列适配机台，结束时间由「数量 ÷ 单位产出」重算；冲突当场拦截并保留用户输入；所有变更写入变更记录，撤销可用。
- **风险高亮**：阻断（红，阻止确认）/ 警告（橙，需知晓）/ 提示（中性）三级，界面同时用图标 + 边框 + 斜纹 + 文字表达，不只依赖红绿。
- **可导入导出**：支持 .xlsx / .csv 导入（浏览器内自行解析 ZIP 与 XML）；导出排产清单、工单、风险清单（.xlsx）、甘特图（.png）与 CSV，文件头写明版本、数据快照、导出范围与确认状态。

### 界面信息架构：同类功能聚合为下拉菜单

早期版本把动作**平铺**在页面上：顶栏 6 个同级按钮、甘特图工具栏 8 个控件、9 项图例铺满一行、
D01 的数据来源与纳入范围各 3 个按钮并排。功能都在，但视觉权重完全相同，看不出主次。
现在按「动作对象」聚合，通用组件是 `components/ui.js` 的 `menuButton()`：

| 位置 | 聚合前 | 聚合后 |
|---|---|---|
| 顶栏 | 排产设置 · 生成计划 · 模拟变更 · 确认版本 · 导出 · 诊断（6 个，占宽 603px） | **生成候选计划**（主操作）+ **计划 ▾**（模拟变更 / 确认版本 / 导出 / 方案版本 / 负荷分析）+ **更多 ▾**（数据来源 / 导入上传 / 清空回到空白 / 排产设置 / 诊断）—— 3 个控件，占宽 309px |
| 甘特图工具栏 | 视角 2 段 + 缩放 3 段 + 工序下拉 + 关键字 + 定位今日 + 定位选中 + 换型条 + 停机（8 个控件）+ 9 项图例平铺 | 视角 2 段 + **筛选 ▾**（工序 / 仅看风险 / 清除）+ 关键字输入 + **视图 ▾**（缩放 / 换型条 / 停机 / 定位）+ **图例 ▾**（11 项，默认收起）—— 5 个控件 |
| 订单中心 | 关键字 + 4 个筛选下拉 + 历史复选框 + 清空（7 个控件） | 关键字 + **筛选 ▾**（优先级 / 交期政策 / 排产状态 / 风险 / 包含历史 / 清空）—— 2 个控件 |
| 数据准备 | 数据来源 3 按钮 + 纳入范围 2 按钮 | **数据来源 ▾** + **纳入范围 ▾** + 「一键收敛」主按钮 |

三个必须守住的设计约束（都有回归断言）：

1. **筛选不能藏起来就「看不见自己开着」**——筛选 / 视图的触发按钮带**生效数量徽标**（比如「筛选 ①」）。
2. **面板里连续调整多个开关不该反复点开**——面板打开时会展开；页面重渲染后由 `syncMenus()` 按 id 复原展开态，
   并把焦点放回刚操作的那一项（捕获阶段记录标识，因为动作的委托处理会先重渲染掉 DOM）。
3. **键盘与读屏可用**：`aria-haspopup="menu"` + `aria-expanded` + `role="menu"/"menuitem"`；
   方向键 / Home / End 在项间移动，Escape 收起并把焦点还给触发按钮；图例这类**静态信息项用 `div` 而不是 `button`**，
   不会被当成可执行项聚焦。

> 顺带修掉一个真实缺陷：弹窗从**菜单项**打开时，菜单已收起，关闭后把焦点还给隐藏元素会被浏览器忽略、
> 焦点掉到 `body`。现在按「触发项 → 所在菜单的触发按钮 → body」三级退让，保证焦点永远不落在虚空里
> （由 `tools/check_a11y.mjs` 的断言守住）。

### 4.1 两套调度算法（可在「排产设置 → 排程策略」切换）

| 策略 | 来源 | 做法 |
|---|---|---|
| **前瞻派单**（默认） | 《路演/三工序排产算法设计》 | **按机台派单**：事件驱动推进时间，机台空闲时做「同型号优先 + 下一台设备前瞻」，把安全等待落成**设备预约**；交期余量分三级（紧急可行 / 普通可行 / 负余量） |
| 按订单排程 | 项目原有实现 | **按订单排产**：逐单把三道工序依次放进最合适的位置（换型感知间隙插入 + R6 惩罚项） |

两套共用同一套数据契约、校验与指标，切换后重新生成计划即可对比。实测（真实脱敏数据 312 单）：

| 指标 | 前瞻派单 | 按订单排程 |
|---|---|---|
| 工序任务 | 903 条 | 903 条 |

### 4.2 目标顺序与约束


**目标顺序（企业口径）**：满足硬约束 → 提升准时交付率 → 减少延期时长 → 改善利用率 / 减少换型。

**算法**：优先级驱动的作业式列表排程 + **换型感知的间隙插入**（insertion heuristic）+ 有界迟到恢复局部搜索。

1. 订单按 `优先级 → 预发货日 → 订单日期 → 订单号` 稳定排序（R1 / R9）。
2. 每张订单沿 拉丝 → 捻股 → 合绳 依次放置，逐工序在**所有适配机台**上枚举可行插入位置，取 `完工时刻 + 0.5 × 换型时长` 最小者，即「交期优先，换型仅在同等交期下优化」。
3. 插入位置同时校验：设备适配（R1）、日历与停机、换型占用（R3 / R4 / R5）、前序完工（R6）、物料就绪；
   评分中对「后序开工 − 前序完工 > 72 小时」按超出量加重惩罚（R6 前瞻）。
4. **R6 等待修复**：对仍然超过 72 小时的相邻工序，在不影响后序开工的前提下把前序任务后移；
   原地放不下时，再尝试在本机台更靠后的空档或**其他适配机台**重放（目标函数改为「完工时刻尽量贴近下游开工」）。
   后移同时受其自身与更前序工序的间隔约束，实时更新时间轴索引，并保证不落入设备停机窗口。
5. 局部优化阶段对迟到订单尝试换机台恢复；**提交前做占用与停机自洽性校验，不通过则整体回滚**。
6. 全流程记录每个任务的候选机台数、评估过的可行位置、换型触发字段与排序依据，供 D04 解释。

**换型耗时模型**（R5 原文「随规格切换幅度变化」）：以关键维度的**相对变化率**度量幅度，`小时 = clamp(1 + 4 × 最大幅度 + 双维度 0.5 + 结构 0.5, 1, 5)`，按 0.5 小时分档。数据包未提供换型耗时矩阵，因此该模型属于**演示参数**，界面与导出文件持续标注。

**产能口径**：

- 拉丝：`加工分钟 = 需求量 ÷ (拉丝速度 m/s × 60)`，适配按设备规格区间判定。
- 捻股：矩阵满足精确模型 `值 = 行捻距均值 × 设备系数`（已用 6473 / 6473 行零误差验证），单位产出由此还原。
- 合绳：显式 rates 矩阵。
- 矩阵空值一律视为**不适配**，不补零、不取均值。

**换型耗时模型（可调，D00 即时生效）**：数据包未提供换型耗时矩阵，按 R5「1–5 小时、随规格切换幅度变化」
建模为 `耗时 = clamp(下限 + 幅度权重 × 最大相对变化率 + 双维度附加 + 结构附加, 下限, 上限)`，
默认 `1 + 4×幅度 + 0.5 + 0.5`，按 0.5 小时分档。下限/上限/权重/两个附加项都在 D00 可编辑并即时重算。

## 七、诚实边界（不吹牛，也不隐藏）

1. **换型耗时、成品 → 股型工艺映射、各工序需求量系数**在数据包中均未提供，当前以**显式标注的演示参数**补齐；启用后版本标记为模拟参数，导出文件持续标注「模拟结果，含未验证参数」，不进入正式已确认状态。
2. **合绳完成 ≠ 实际发货**。界面用「预计合绳完工」与预发货日对比，作为赛题范围内的**交付预测代理指标**；出厂后的检测、包装、运输缓冲需企业确认。
3. **未接 ERP / MES**，确认动作仅表示本产品内的人工认可，界面不显示「已下发生产」。
4. 未实现完整制造流程、移动端、多工厂优化；质量分析是另一加分方向，本方案优先实现设备负荷分析。
5. 待企业确认的问题（设备台数以清洗后台账为准、软交期宽限是否可正式确认、R6 的 3 天是连续 72 小时还是生产日等）在 D00 规则摘要中逐条标注为「待确认」。
6. **换型口径的两个细节**：① 派单器原始输出与最终上报的换型总时长**完全一致**（1,617 h / 771 条含换型，差 0.0 h），说明后处理没有篡改换型总量；
   ② 但独立核验（`tools/check_dispatch.mjs`）会报出 12 条任务的换型值与其「机台首个任务应保守计初始换型」的期望不一致——
   属后处理换机台时的边界情形。试过把这类候选一律拒绝，换型口径是干净了，但 **R6 换机台修复路径被堵死**：阻断级 R6 从 7 处涨到 63 处。
   硬约束优先于口径细节，因此保留现状并如实披露，而不是改成一个更好看的数字。
7. **界面首次排产仍可能显示旧算法结果**：切换「排程策略」后必须重新生成计划才生效（已生成的历史版本不会自动重算）。

3. `raw()` 包装对象没有 `toString / valueOf`，任何「空格 + raw(...)」拼接都会得到 `[object Object]`（组件层两处）。
4. **甘特图布局方向错误**：`.gantt-inner` 用了 `display:flex` 的默认横向排列，时间轴表头与任务行左右并排，
   其中一侧被挤出视口 —— 表现为「时间轴在、任务行空白」或反之。Node 级断言只看 HTML 字符串，抓不到这类布局缺陷，
   是在 headless Chrome 截图复核时发现的。已改为 `flex-direction: column`。
### 空白启动（第三次改造：打开即为空，上传文档才出结果）

原先应用在启动时自动 `fetch('data/dataset.json')` 并首排 —— 页面从没出现过「还没有数据」的状态，
「上传 → 处理 → 显示」这条主流程实际上是被跳过的。改为空白启动后，由 `tools/check_blank.mjs`
（新增 36 项真浏览器断言）守住，并**顺带抓出两个此前一直存在、但因为没有对照物而看不出来的真实缺陷**：

| 缺陷 | 后果 | 修复 |
|---|---|---|
| `data/deviceImport.js` 按 (品名,规格) 去重时**直接丢弃后续重复行**，而 `build_dataset.py` 的 `dedup_rows` 会把后续行里「首次出现为空」的单元格**回填**进来 | 同一台机在另一捻距档位里有产出，导入路径却判它「不适配」→ 机台可用集合偏小 | 去重逻辑改为与 python 完全一致的「首次优先 + 空缺回填」，并记录 `variants` / `variantConflict` |
| `engine/spec.js` 的 `parseSpec` 要求股数后**紧跟 `*`**，而 python 的 `parse_spec` 取的是 `*` 之前的前导数字 | `35W*K7+WSC` 这类规格（**104 张订单、40 个不同规格**）股数/股型解析为 `null` → 股数按 1 算 → 捻股与拉丝需求量、工时、机台占用全错 | 逐条对齐 python 语义（前导数字 + 字母后缀、结构保留原样、绳芯按标签域取值、`lay` 用规范值 `Z`/`S`）；中文捻向移到展示层 `layLabel()` |

两条路径此前从未被放在一起比对过。现在 `tools/check_blank.mjs` 会**逐条**断言「界面导入」与「预置快照」的
任务集合（订单 × 工序 × 机台 × 起止）完全相同，并用 323 张订单 × 9 个字段（2907 格）比对两个规格解析器。
修复后两者**逐字节一致**：903 条任务、96.5% 准时率、20 项阻断，全部相同。

## 十、生产化能力

### 10.1 持久化与恢复（IndexedDB）

刷新即丢失版本与确认记录，是早期版本最实质的落地缺口（前端审查报告 P2-7）。现已实现浏览器端持久化：

| 能力 | 说明 |
|---|---|
| 会话恢复 | 数据快照、方案版本、当前指针、排产设置全部落盘；**刷新后自动恢复**，并在顶栏给出「已恢复上次会话（N 个版本，已确认 M 个）」，可一键「放弃恢复并重新开始」 |
| 干净启动 | 访问 `?data=demo&fresh=1` 清空本地持久化并重新首排；应用会**自动把 fresh 参数从地址栏剥离**，避免手动刷新时反复回到干净会话 |
| 降级策略 | 环境不支持（隐私模式）、配额不足、写入失败都**不影响排产主流程**，只在界面如实告知状态；配额不足时自动暂停持久化并给出清理入口 |
| 版本号分配 | 版本号在「内存中的 id ∪ 持久化中的 id」上分配，避免干净启动后新版本与磁盘旧版本撞车被乐观锁误判为冲突 |
| 数据结构版本 | 持久化带 `SCHEMA_VERSION`，不匹配时按策略处理并给出可读原因，不静默读坏数据 |

### 10.2 审计轨迹

- **追加式日志**：数据载入、排产、人工调整、锁定/解锁、执行冻结、确认版本、复制草稿、一键收敛、采用模拟方案、替换设备数据、清空持久化，全部写入只增不改的审计日志。
- **版本内容指纹**：每个版本记录基于「任务表 + 排除清单 + 计划窗口」的 FNV-1a 内容指纹，用于变更比对。界面如实标注这是**内容指纹而非加密签名**，不声称防篡改。
- **可导出**：导出面板新增「审计日志 .csv」，带抬头声明（导出时间 / 操作者 / 数据快照 / 口径说明）与完整轨迹。

### 10.3 同源多标签页协同

两个标签页打开同一工作台时，通过 `BroadcastChannel` 交换版本变更：
检测到「同一版本的内容指纹已不同」或「另一标签页确认了该版本」时，顶栏给出黄色冲突横幅，
提示重新载入或基于当前版本复制草稿，**不做静默覆盖**。
保存时还有基于版本修订号（`rev`）的乐观锁：只有当磁盘记录确实比本地版本更新时才判为冲突。

### 10.4 可观测与诊断

- **全局错误边界**：`window.onerror` 与 `unhandledrejection` 统一收敛到结构化日志环形缓冲（300 条），同一错误去重，界面给出非阻塞提示。
- **诊断面板**（顶栏「诊断」）：应用与数据结构版本、持久化状态与存储占用、数据快照与设备来源、版本列表与内容指纹、最近审计、最近日志。
- **诊断包导出**：一键导出 JSON（**订单号自动打码**），出问题时能复现「发生了什么、什么数据、哪个版本、哪个操作者」。
- **立即保存 / 清空持久化**：诊断面板内可直接操作，便于演示与排障。

### 10.7 可访问性与键盘可用性

- **焦点管理**：抽屉与弹窗具备 `role=dialog` / `aria-modal` 与可访问名称，打开时焦点进入对话框、Tab 在内部循环、Escape 关闭后**焦点回到触发元素**，多层弹层只陷阱最上层。

- **其他**：跳到主内容链接、`prefers-reduced-motion` 关闭动效、`prefers-contrast` 提高对比、交互元素统一的 `:focus-visible` 轮廓。
