## 2. 状态机

### 2.1 数据快照状态（空白 / 半份 / 齐备）

判据函数：`store.intakeStatus()`（`store.js:340-352`）——`ready = missing.length === 0`，`missing` 取值只有两个字符串：`'订单文件'`、`'设备 / 产能文件'`。

| 状态 | 判定条件 | 系统表现 | 依据 |
|---|---|---|---|
| 空白 | `snapshot.orders.length === 0` 且设备台数 `= 0`（`blankSnapshot()`） | 视图层 `if (!s.snapshot)` 分支实际不会命中（resetToBlank 会给一份空白快照）；工作台显示空态「还没有排产结果」；`gate()` 在无 snapshot 时返回「尚未载入数据快照」 | `store.js:51-67`、`store.js:330-338`、`store.js:366`；`main.js:143-147`；`workbench.js:13-14` |
| 半份（只有订单） | orders > 0，devices = 0 | `missing = ['设备 / 产能文件']`；`settleIntake()` Toast（warn）「还缺少：设备 / 产能文件，补齐后会自动生成首排计划」并跳「数据准备」；**不排产** | `store.js:348-351`；`main.js:544-548` |
| 半份（只有设备） | orders = 0，devices > 0 | `missing = ['订单文件']`；同上提示；`applyDeviceData` 显式为「先传设备再传订单」保留通道（空白时以设备为底座） | `store.js:310-317`；`main.js:544-548` |
| 齐备 | 两者 > 0 | `ready = true` → `settleIntake()` 自动首排：Toast「订单 N 条 · 设备 M 台已就位，正在生成首排候选计划…」→「首排候选计划已生成」 | `main.js:549-553` |

**禁止动作与后果**

- 半份数据不得排产：`settleIntake()` 在 `!ready` 时直接 `return false`，不调用 `generate`（`main.js:544-548`）。
- 打开页面时若路由非法，退回工作台或数据准备（`main.js:150-155`）。
- 替换数据（订单或设备）后：所有既有版本 `basedOnOldData = true`，当前版本指针清空，基线清空，`simulation` 清空（`store.js:282-288`、`store.js:319-320`）；版本标签显示「基于旧数据」（`components/ui.js:518-520`），工作台额外显示灰色横幅「当前版本基于已替换的数据快照…如需按当前数据排产请重新生成」（`workbench.js:27`）。
- `resetToBlank()` 清空快照与内存版本，但**不删除**已落盘版本与审计（`store.js:329-337`）；确认弹窗原文见 §6。

### 2.2 版本状态

存储字段：`version.status`（`'draft' | 'stale' | 'confirmed' | 'superseded'`）+ `version.dirty` + `version.basedOnOldData` + `version.simulated`（`store.js:468-488`、`store.js:628`、`store.js:647`、`store.js:282`）。

界面标签唯一来源 `versionTag()`（`components/ui.js:516-525`）：

| 展示标签 | 条件 | 依据 |
|---|---|---|
| 基于旧数据 | `v.basedOnOldData` 或 `v.datasetKey !== state.datasetKey` | `ui.js:518-520` |
| 已确认（模拟参数） | `status==='confirmed' && simulated` | `ui.js:521` |
| 已确认 | `status==='confirmed'` | `ui.js:521` |
| 已替代 | `status==='superseded'` | `ui.js:522` |
| 待重算 | `status==='stale' || v.dirty` | `ui.js:523` |
| 可确认 | `validation.canConfirm === true` | `ui.js:524` |
| 草稿（存在阻断） | 其余情况 | `ui.js:524` |

`load.js:12` 另有等价简表：`{ draft: '草稿', stale: '待重算', confirmed: '已确认', superseded: '已替代' }`。

**迁移条件**

| 从 → 到 | 触发 | 依据 |
|---|---|---|
| ∅ → 草稿（draft） | `generate()` 产出新版本，`status:'draft'`、`rev:1`、写入指纹 | `store.js:468-489` |
| 草稿 → 待重算（stale + dirty） | 任何人工改动（`updateTask`） | `store.js:521-522` |
| 草稿 → 可确认（标签态，非 status 值） | `validation.canConfirm === true` | `ui.js:524` |
| 草稿 → 已确认 | `confirmVersion()`：`canConfirm` 且 `!dirty` 且（无延期或已勾选知晓） | `store.js:641-648` |
| 已确认 → 已替代 | 新版本确认时，遍历所有 `confirmed` 置 `superseded` | `store.js:647` |
| 已确认 → 新草稿 | 对已确认版本做任何编辑：`ensureEditable()` 自动 `copyAsDraft()` 并 Toast「已确认版本不可原地编辑，已基于 V1 派生草稿 V2 并在此修改」 | `store.js:504-513` |
| 任意 → 基于旧数据 | 载入新订单快照 / 替换设备数据 | `store.js:282`、`store.js:319` |
| 待重算 → 可确认 | `undoLast()` 后该版本已无任何人工变更且 `changes.length===0` → `dirty=false; status='draft'` | `store.js:556-557` |

**禁止动作与提示原文**

- 有阻断：`confirmVersion()` → Toast（err）「存在 N 项阻断问题，无法确认版本」；确认弹窗按钮 `disabled`（`store.js:643`；`main.js:242`）。
- 有未重算修改：Toast（err）「存在未重算的修改，请先重算再确认」（`store.js:644`）。
- 有延期未勾选：Toast（err）「存在延期订单，需勾选「已知晓」后才能确认」（`store.js:646`）。
- 确认语义边界（弹窗副标题原文）：「确认表示本产品内的人工认可；由于未接 ERP/MES，不显示「已下发生产」」（`main.js:244`）。
- 已确认版本不可原地编辑（版本页横幅）：「确认后版本不可原地编辑；如需调整，用「复制为草稿」派生新版本。新版本确认后旧版留存并标为「已替代」。」（`versions.js:38-40`）。

**迁移与禁止**

- 锁定/解锁：`toggleLock`；若已冻结 → Toast（err）「该工序已开工/完工，属于执行冻结，不能用普通解锁解除」，且不解锁（`store.js:530`）。
- 冻结：`setFrozen(taskId, true)` 强制 `locked = true`；反向 `setFrozen(id,false)` 只清 `frozen`（`store.js:539-547`）。
- 锁定/冻结不改变 `dirty`（`toggleLock`/`setFrozen` 未设置 dirty）；只有 `updateTask` 会把版本置为 `stale`+`dirty`（`store.js:521-522`、`store.js:527-547`）。
- 重算时锁定与冻结会被恢复：`generate()` 从 `keepLocksFrom` 或当前版本收集 `locks`/`frozen`，排程后重新打标（`store.js:407-411`、`store.js:446-448`）；顶栏生成按钮传 `keepLocksFrom: v?.id`（`main.js:186`）。
- 撤销只针对 `changes` 里带 `before` 的记录（`store.js:551`）。

## 附：导入能力（订单 / 设备）

### 订单文件

- 入口：「数据准备」页订单槽，支持 `.xlsx` / `.csv`，单文件 ≤ 20MB（`dataPrep.js:112`、`dataPrep.js:125`）。
- 读取器：`readXlsx(fileOrArrayBuffer, options)` / `readCsv(fileOrText)` / `guessColumnMapping(headers, targetFields)`（`xlsxReader.js:6-8`、`xlsxReader.js:693`、`xlsxReader.js:912`、`xlsxReader.js:952`）。
- 技术约束：原生 ES Modules、零第三方依赖、零 CDN；仅用 DOMParser、DecompressionStream、TextDecoder、Blob/Response（`xlsxReader.js:3-4`）。
- 约定：`rows[0]` 为表头；空值统一 `null`；每张表用中央目录 CRC-32 校验，长度或校验和不符一律抛可读错误（`xlsxReader.js:11-17`）。
- 资源上限：`DEFAULT_READ_LIMITS`（`maxRows`/`maxCols`/`maxCells`/`maxPartBytes`），超限错误写明「哪张表、超了哪个限制、当前值」（`xlsxReader.js:17-19`、`xlsxReader.js:666`）。
- 目标字段 13 个（`dataPrep.js:325-339`）；必需字段 4 个：订单号 `id`、规格 `spec`、业务数量 `qtyMeters`、预发货日 `preShipDate`（`dataPrep.js:369`）。

### 设备 / 产能文件

- 对象是《产品额定（平均值）.xlsx》三张表：拉丝（设备台账）/ 捻股（品名 × 规格 × 每设备每分钟平均产出米数矩阵）/ 合绳（绳子+绳芯）（`deviceImport.js:2-6`）。
- 表名别名匹配：`拉丝` / `捻股` / `合绳（绳子+绳芯）`（含半角与省略写法）（`deviceImport.js:13-17`）。
- 产出结构与 `data/dataset.json` 的 `machines` / `capacity` 一致，交给 `store.applyDeviceData` 替换快照设备与产能（`deviceImport.js:7-8`）。
- 关键约定原文：「矩阵空值或非正值一律视为「不适配」，写成 null，绝不补 0 或补均值。」（`deviceImport.js:10`）
- 导出函数：`findDeviceSheets(parsed)`、`looksLikeDeviceWorkbook(parsed)`、`parseSpecRange(raw)`、`parseDeviceWorkbook(parsed)`（`deviceImport.js:18`、`:31`、`:51`、`:162`）。
- 规格区间解析：`"0.4-0.75"` / `"0.25~0.6"` → `[min, max]`（`deviceImport.js:50-56`）。
