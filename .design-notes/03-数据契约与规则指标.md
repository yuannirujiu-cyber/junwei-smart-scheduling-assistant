#### 1.1.1 processMap 的两种写法（`DATA_CONTRACT.md:48-78`）

- **默认三工序历史写法**：`{ closingSpec, closingName, strandName, strandSpec, wireSpecMm, status }`，示例见 `DATA_CONTRACT.md:53-57`；演示订单 `processMap` 实际字段为 `closingSpec / closingName / strandName / strandSpec / wireSpecMm / qtyFactor / status`（`data/demo-dataset.json`，如 `DEMO-2026-0001`）。
- **任意工艺链通用写法**：`{ [工序key]: { spec, name, specMm } }`，示例见 `DATA_CONTRACT.md:63-68`。
- 通用路径规格解析优先级（**不臆造**，`DATA_CONTRACT.md:71-76`）：① `processMap[工序key].spec/.specMm`（人工确认，最高）→ ② 订单规格归一化键与该工序矩阵行匹配（唯一命中自动关联；多命中取首行并标注「待人工确认」）→ ③ 该工序矩阵只有一个规格时取唯一候选（标注演示参数）→ ④ 都不成立记「规格缺口」，订单进阻断清单并给修复建议。

### 1.3 产能矩阵 Capacity Matrix（`capacity`）

**工厂含义**：设备—规格适配关系表；**行 = 规格，列 = 设备**，单元格 = 该设备生产该规格的单位产出（`docs/ENGINE_API.md:174`）。
**契约**：`docs/DATA_CONTRACT.md:98-129`；真实口径 `data/README.md:83-93`。

**矩阵级字段**

| 字段名 | 中文标签 | 单位 | 取值 / 示例 | 必填 |
|---|---|---|---|---|
| `machineIds` | 设备列顺序 | — | 数组；与 `rates`、`coefficients` **按下标对齐**；真实捻股 51 项、合绳 11 项 | ✔ |
| `rows` | 规格行 | — | 数组；真实捻股 3211 行、合绳 3472 行 | ✔ |
| `coefficients` | 设备系数 | — | 仅捻股；长度必须 = `machineIds`，否则 `COEFF_LENGTH` | ✖ |
| `model` | 模型口径说明 | — | 捻股 `torsion-x-coefficient`；合绳 `explicit` | ✖ |
| `unit` | 单位 | — | 两矩阵均为 `米/分` | ✖ |

**矩阵行字段**

| 字段名 | 中文标签 | 单位 | 取值 / 示例 | 必填 |
|---|---|---|---|---|
| `spec` | 规格 | — | 合绳 `"12mm 6*19S+FC"`；捻股股径 `"0.64"` | ✔ |
| `name` | 品名 | — | 与 `spec` 组成 `name\|spec` 精确查找键 | ✖ |
| `rates` | 单位产出 | 米/分 | 数组，长度必须 = `machineIds`，否则 `RATES_LENGTH`；演示合绳 `[12.0, 9.6, 8.64, 7.2]` | ✖ |
| `torsion` | 行捻距均值 | mm | 演示捻股 `22.0`；真实 4.15–211.2 | ✖ |
| `caps` | 显式适配设备 | — | 编号或下标数组；给出后**优先于 rates**；真实仅合绳 2 行带 `caps`（`[0..9]`） | ✖ |
| `capCount` | 展示用适配台数 | 台 | 真实捻股非全适配 1001/3211 行、合绳 2/3472 行 | ✖ |
| `variants` / `variantConflict` | 去重合并份数 / 数值分歧标记 | — | 按 (品名,规格) 去重时保留首次出现值并打标（`data/README.md:132-134`） | ✖ |

**空值语义（重要，`DATA_CONTRACT.md:120-129`）**

```
rates[i] == null 或 <= 0  → 该规格在设备 i 上「不适配」（不是 0 产能，也不是可用）
caps 给出时               → 以 caps 为准（未列入的设备不适配）
行不存在 / 矩阵键不存在    → 不适配（绝不补零、不取均值）
```

校验器给出 `MATRIX_NULL_CELL`（逐行汇总哪些设备列是空的）与 `MATRIX_ROW_INADAPTABLE`（整行无可用产出）警告；排产时这些设备列不被使用，若整单因此无设备可加工 → 记「未排产」+ 阻断风险。

### 1.6 工序 Process / Stage（ProcessDef）

**工厂含义**：工艺链上的一道加工环节；内置默认链 = **拉丝 → 捻股 → 合绳**（`web/src/engine/chain.js:22-56`，与旧版 `rules.PROCESSES` 完全一致）。
**契约**：`docs/ENGINE_API.md:142-166`；注入优先级 `options.processChain > options.processes > dataset.processChain > dataset.meta.processChain > 内置默认链`（`ENGINE_API.md:148`）。

### 1.7 规格 Spec

**工厂含义**：贯穿全链的「加工对象标识」——订单规格（成品绳）、合绳矩阵规格、捻股股径规格、拉丝原料（单丝）直径。
**契约**：解析实现 `web/src/engine/spec.js`（与 `tools/build_dataset.py` 的 `parse_spec` 逐条对齐，两条路径必须给出同一份解析结果，`spec.js:8-9`）。

- **订单/合绳规格形如**：`"22mm GT8ZH(8*K26WS+IWRC)"`、`"9-12mm GT8Z(8*K19S+IWRC)"`、`"44mm 6*36WS+IWRC"`（`spec.js:2-3`）。
- **捻股矩阵**：品名 `"光面股0064 1*3 B1"` + 规格 `"0.64"`（股径 mm）（`spec.js:4`）。
- **归一化键** `normKey`：`直径|结构`（去空白转大写），如 `"22mm GT8ZH(8*K26WS+IWRC)" -> "22|8*K26WS+IWRC"`（`spec.js:72-80`、`data/README.md:100-107`）。
- **推导辅助**（`data/spec-derivation.json`）：`strandCountFactor = { 股数N: sin(π/N) }`（4 位小数，19 个 N 值：3→0.866 … 40→0.0785）；`strandSpecValues` = 捻股表规格列全部 distinct 数值升序（926 个，0.64 起）。用途：`d ≈ D · sin(π/N)` 换算（D 股径、d 丝径）（`data/README.md:109-111`）。

## 2. 三道工序：输入 / 输出 / 适配 / 单位产出 / 工时

| 维度 | 拉丝 drawing | 捻股 stranding | 合绳 closing |
|---|---|---|---|
| 中文名 / 短名 | 拉丝 / 拉 | 捻股 / 捻 | 合绳 / 合 |
| 设备编号前缀 | `81` | `82` | `83` |
| 输入 | 盘条钢材 → 单丝（原料规格 `wireSpec`，mm） | 多根钢丝 → 「股」（结构 + 股径） | 多股 → 钢丝绳成品（绳径 + 结构） |
| 输出 | 规定直径的**钢丝**（加工规格 = `specMm`） | **股**（矩阵行的 `name` + 股径 `spec`） | **成品钢丝绳**（订单规格本身即合绳产出，`mapping.js:47`） |
| 适配判定方式 | **规格区间**：设备 `specMin ≤ wireSpecMm ≤ specMax`（`capability.kind='specRange'`） | **产能矩阵**：`stranding` 矩阵，行 = 股规格，列 = 设备（`kind='matrix'`） | **产能矩阵**：`closing` 矩阵，行 = 绳规格，列 = 设备 |
| 单位产出（米/分） | `speedMps × 60`（`ENGINE_API.md:173`） | `行捻距 × coefficients[设备列]`；无 `rates` 时用系数模型（捻股 model = `torsion-x-coefficient`） | `rates[设备列]` 查表（合绳 model = `explicit`，**不满足系数模型，必须查表**，`data/README.md:87`） |
| 工时公式 | `加工分钟 = 需求量 ÷ (speedMps × 60)`，**向上取整**（`README.md:163`、`model.js:89-93`） | 同式：`需求量 ÷ 单位产出`，向上取整 | 同式，向上取整 |
| 需求量（逆推） | 拉丝 = 捻股 × 丝数 × 1.02 | 捻股 = 合绳 × 股数 × 1.02 | 合绳 = 订单米数 × 1.00 |
| 等待上限 | 与捻股间隔 ≤ 72h（R6） | 与合绳间隔 ≤ 72h（R6） | 末道工序，无下游等待 |

**需求量完整公式**（`web/src/engine/mapping.js:129-138`，默认 `qtyModel` 见 `mapping.js:8-13`）：

```
合绳 closed   = 订单米数 × closingFactor(1.00)
捻股 stranded = 合绳 × 股数 n × strandShrink(1.02)      // 捻缩系数
拉丝 drawn    = 捻股 × 丝数 × drawShrink(1.02)           // 捻缩/损耗
```

- **股数 n** 取订单规格解析的 `strandCount`（缺则 `1`，绝不默认 0 股，`mapping.js:131`、`model.js:80-81`）。
- **丝数** `wireCountOf(股结构)`：`K26WS→26`、`1*19→19`、`1+9+9→19`、`19S→null`；未知时用 `defaultWireCount = 19`（演示参数）（`spec.js:84-97`、`mapping.js:117`）。
- 演示订单还额外带 `processMap.qtyFactor`（`{drawing:1.02, stranding:1.0, closing:1.0}`），但**引擎的默认三工序需求量走 `DEFAULT_QTY_MODEL`**（见 §10 备注）。

**工艺映射推导（拉丝/捻股的具体规格从哪来）**：数据包**没有**成品→股型映射表，因此 `resolveMapping` 的策略是「自动给出候选 + 明确标注来源」（`mapping.js:1-4`）：

1. 合绳规格：`processMap.closingSpec`（人工确认）→ 归一化键唯一命中自动关联 → 多候选按品名相似度择一（标注「待人工确认」+ 演示参数）→ 否则记缺口（`mapping.js:47-70`）。
2. 捻股股型：`processMap.strandName`（人工确认）→ 否则按几何推导股径 `d ≈ πD/(N+π)`（`estimateStrandDiameter`，`mapping.js:24-28`）就近匹配（容差 `max(0.05, 8%)`），再按丝数/涂层择优 → 仍无则取全局最近邻（标注演示参数）（`mapping.js:72-113`）。
3. 拉丝原料：`processMap.wireSpecMm`（人工确认）→ 否则 `单丝直径 = 股径 / √丝数`（`estimateWireDiameter`，`mapping.js:30-34`）推导（标注演示参数）；随后校验是否有拉丝机规格区间覆盖该直径（`mapping.js:116-127`）。

## 3. 规格解析：一个成品规格由哪些维度组成

**代码事实**：`web/src/engine/spec.js:26-64`（`parseSpec`），正则 `spec.js:10-14`；字段表 `data/README.md:72-75`。

以 `"22mm GT8ZH(8*K26WS+IWRC)"` 为例（实跑输出）：

| 维度（字段） | 中文名称 | 取值域 / 规则 | 本例值 |
|---|---|---|---|
| `raw` | 规格原文 | 去首尾空白 | `22mm GT8ZH(8*K26WS+IWRC)` |
| `diameterMm` | 绳径（公称直径） | 数字，单位 mm；正则 `^([0-9]+(\.[0-9]+)?)mm\s+(.+)$`（数字与 mm 之间无空格） | `22` |
| `diameterRaw` | 绳径原文（区间等） | 宽松式 `^([0-9.]+([-~][0-9.]+)?)\s*mm\s*(.*)$` 命中时记原文；含 `-`/`~` 时 `note='直径为区间，需人工确认取值'` | `null` |
| `grade` | 牌号 | `GT + 数字 + 大写字母`，形如 `GT[0-9]+[A-Z]*` **且带括号**才识别；如 `GT8ZH`、`GT28ZD-H`（含连字符时**不剥离括号**，见 §10） | `GT8ZH` |
| `lay` | 捻向 | 牌号末位 `Z`（右捻）/ `S`（左捻），数据层只存规范值；展示层 `layLabel()` 转「右捻(Z)」/「左捻(S)」（`spec.js:67-69`） | `null` |

| `strandCount` | 股数 | 结构里**第一个 `*` 之前**的前导数字；字母后缀（如 `35W`）是股型标记，不阻断解析 → `35W*K7` 股数 = 35 | `8` |
| `strandConstruction` | 股结构（股型） | 第一个 `*` 之后、第一个 `+` 之前的部分，**保留前导 K** | `K26WS` |

| `parseOk` | 是否解析成功 | **只取决于绳径是否解析出来**（与 python 一致） | `true` |
| `note` | 备注 | 空规格 / 区间直径 / 无法解析为「直径mm 结构」格式 | `null` |

**实跑样例（可复现）**：

| 输入 | `parseOk` | 关键结果 |
|---|---|---|
| `"12mm 6*19S+FC"` | true | 直径 12、无牌号、结构 `6*19S+FC`、股数 6、股结构 `19S`、绳芯 `FC`；`normKey = "12\|6*19S+FC"` |
| `"9-12mm GT8Z(8*K19S+IWRC)"` | **false** | `diameterMm = null`、`diameterRaw = "9-12"`、note「直径为区间，需人工确认取值」；`normKey = null` → 订单 `matchStatus = missing` |
| `"44mm 6*36WS+IWRC"` | true | 直径 44、结构 `6*36WS+IWRC`、股数 6、股结构 `36WS`、绳芯 `IWRC` |
| `"35mm 35W*K7+WSC"` | true | 直径 35、结构 `35W*K7+WSC`、**股数 35**、股结构 `K7`、绳芯 `WSC`；`normKey = "35\|35W*K7+WSC"` |
| `"35W*K7+WSC"`（**仅结构串，无绳径**） | **false** | 结构解析成功（股数 35 / 股结构 K7 / 绳芯 WSC），但 `diameterMm = null`、`parseOk = false`、note「规格无法解析为「直径mm 结构」格式」；`normKey = null` |
| `"24mm GT28ZD-H(28W*K7+WSC)"` | true | **牌号未剥离**（含连字符）：`grade = null`，`structure = "GT28ZD-H(28W*K7+WSC)"`、`strandCount = null`；`normKey = "24\|GT28ZD-H(28W*K7+WSC)"`（属已知预期差异，见 §10） |

> 结论：**「35W*K7+WSC」这类结构串本身不是完整的订单规格**，必须写成 `"35mm 35W*K7+WSC"` 才会 `parseOk = true` 并产生归一化键。

### 5.3 对版本确认的影响

- `canConfirm = (blocks.length === 0)`，即**只要有一条阻断级风险就不能确认**（`validate.js:195-201`）。

## 7. 解释结构（D04「依据」页签）

**实现**：`web/src/engine/explain.js`（文件头注释：「结构固定为：结论 → 具体约束 → 证据 → 可操作入口 / 全部由结构化计算结果驱动，**不做语言模型的自由发挥**」，`explain.js:1-3`）。
**渲染**：`web/src/views/taskDrawer.js:109-122`（`tabWhy`），返回结构 `{ conclusion, evidence[], constraints[], actions[], caveats[], rules[], ruleTexts[] }`（`explain.js:125-129`）。抽屉三个页签 = **安排 / 依据 / 变更记录**（`taskDrawer.js:21-25`）。

页面骨架：**「结论」卡（含「命中规则 R1 R5 R3 …」徽标行）→「具体约束」列表（每行 = 规则徽标 + 文案）→「证据」块（每块 = 标题[+规则徽标] / 值 / 「来源：…」）→ 底部灰条免责声明**（原文：「解释由结构化计算结果驱动；无证据的原因显示为「需要核实」，不做「最优」「唯一可行」等无依据断言。」，`taskDrawer.js:120-121`）。

### 8.2 演示参数的完整清单（`docs/ENGINE_API.md:56-138`）

| 参数组 | 字段 | 默认值 | 物理含义 |
|---|---|---|---|
| `changeoverModel` | `minHours` | `1` | 换型耗时下限（同结构小幅度切换） |
| （R5） | `maxHours` | `5` | 换型耗时上限 |
| | `magnitudeWeight` | `4` | 幅度权重（1 小时 / 满幅） |
| | `bothDimsBonus` | `0.5` | 同时切换两个维度的附加耗时 |
| | `structuralBonus` | `0.5` | 结构 / 原料类切换的附加耗时 |
| `qtyModel` | `closingFactor` | `1.00` | 合绳需求量 = 订单米数 × 1.00 |
| | `strandShrink` | `1.02` | 捻缩系数 |
| | `drawShrink` | `1.02` | 拉丝损耗 / 捻缩 |
| | `defaultWireCount` | `19` | 股结构未知时的丝数缺省值 |
| `setupWeight` | — | `0.5` | 换型占用权重：目标 = 完工时刻 + W × 换型时长；W=0 纯交期优先，W 越大越倾向少换型（`ENGINE_API.md:65`） |
| 其他 | `demoParams` | `{enabled:false}` | 兼容旧版「演示参数模式」开关 |
| | `horizonDays` | 自动（30…200，按最晚交期 + 21 天） | 计划窗口天数 |
| | `planStart` | 自动（未结束订单最早日期当天 00:00） | 计划起点 |

**换型耗时公式（R5，`ENGINE_API.md:98-108`、`web/src/engine/spec.js:180-197`）**：

```
hours = clamp( minHours + magnitudeWeight × 最大相对变化率
             + (切换维度 > 1 ? bothDimsBonus : 0)
             + (结构/原料类切换 ? structuralBonus : 0),
             minHours, maxHours )
相对变化率 = |a−b| / max(|a|,|b|)；无法量化的结构类字段按满幅 1（保守取大）
结果按 0.5 小时分档；默认 = 1 + 4×幅度 + 0.5（双维度）+ 0.5（结构），上限 5 小时
```

分档文案 `setupTier`（`spec.js:189-195`）：`大幅`（幅度 ≥ 60%）/ `中等幅度`（≥ 25%）/ `小幅`；前缀「双维度切换」或「单维度切换」；完整形如「双维度切换 · 大幅（幅度 80%，模型 1~5h）」。无换型 → `tier = '同规格连排，无需换型'`；首次上机 → `'首次上机（无前序任务）'`。

> **注意（两套换型口径并存，事实陈述）**：`spec.js`（按订单排程路径）用上述「幅度模型」；**前瞻派单路径在 `web/src/engine/dispatch.js:84-116` 另有一套**：拉丝固定 `drawingSetupMin` 60 min；捻股/合绳 = **目标订单股数 × `perStrandSetupMin` 10 min**，超出 R5 上下限时按 `clampToR5` 夹紧并披露 `clamped`；股数解析不到按最坏值 `unknownStrandSetupMin` 计（「§2.1 不允许默认 0 股」）。实跑前瞻派单的 `setupTier` 取值为 `首次上机` / `规格切换` / `同型号无需换型`（`dispatch.js:309`），触发字段显示如「8 股 × 10 min = 80 min」。

### 8.3 日历与就绪（R2）
